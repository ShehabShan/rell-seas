# Skill: Concept Design

Used in Phase 3, once, after Phase 2's synthesis is approved.

## Input
`build/phase-2-synthesis.md` (the ranked needs, named conflicts, named gaps).

## What to do
Generate 3–4 server concepts that are genuinely different from each other — different core identity hooks and different structural choices, not the same skeleton with different channel names. Each concept should resolve the Phase 2 needs and conflicts in its own way; if two concepts make the same call on every major conflict, they're not actually different concepts.

For each concept, define:
- **Core identity hook** — the one-line idea that makes this server feel unique (the research mentions ideas like a Lineage Manifest, a Crucible, a crew academy, a sneaks vault — use these as inspiration, not a checklist to include all of).
- **Category/channel skeleton**, high level only (≤8 categories, per `findings/discord-architecture-research.md`'s lean-launch doctrine — don't design individual channels yet, that's Phase 5).
- **Role ladder**, high level.
- **What makes it feel premium without any paywall.**
- **What's deliberately left out at launch** (lean-launch doctrine again — a server that tries to have everything on day one usually feels emptier, not fuller).
- **Which Phase 2 needs and which insight cards it's responding to** — cite card ids.

## Rules
- Don't score or rank the concepts here — that's Phase 4.
- Don't write actual channel names or exact copy — stay at the structural level.
- Every concept must trace back to something in Phase 2, not to a generic "good Discord server" template.
