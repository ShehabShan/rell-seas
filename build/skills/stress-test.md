# Skill: Stress Test

Used in Phase 4, once.

## Input
`build/phase-3-concepts.md`.

## Rubric
Score each concept 1–5 on each row, with a one-line justification per score:
1. **Constraint fit** — free, no P2W optics, premium feel without money gates.
2. **Operability** — can one person, checking in every 10–15 minutes with no dedicated mod team yet, actually run this? How much does automation (AutoMod, verification level, report flow) cover versus how much needs a human watching live?
3. **Fan-run safety** — disclaimer placement, no official-asset reuse risk.
4. **Resolves top-volume needs** — pull the actual top-10 cards from `insights/insights.stats.md` and check whether the concept's decisions address them.
5. **Freshness risk** — does the concept lean on any fact that's still a research-snapshot? Flag it rather than silently assuming it still holds.
6. **Day-one survival** — a server that looks great at 500 members can feel dead at 5. Does this concept give early joiners something to do?

## Output
A scored comparison table, then a clear recommended default with one-line reasoning, and the runner-up with why it lost. Per `AGENTS.md`'s decision rule, present this as "I recommend X because Y," with the runner-up named for context — not as an unprioritized menu.

## Rules
- Justify every score; a number with no reasoning is not useful to the owner.
- If two concepts tie closely, say so plainly rather than forcing a false margin.
